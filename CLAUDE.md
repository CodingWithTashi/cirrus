# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

LastPuff — a quit-vaping Flutter app (store name **Cirrus**, never "Circus"; the App Store record carried that misspelling until Sep 2 2026). The brand owns **cirrusquit.com** — the marketing site (`cirrus-landing`, Astro on Cloudflare Pages) and, once `S5-11` lands, the `/privacy` and `/terms` the app links. The data layer is **API-shaped with two backends behind one seam**: session lifecycle and all persistence go through async repositories over the domain contracts. `backendModeProvider` picks who answers — **mobile (Android/iOS) runs real Firebase**, while desktop/web/tests stay on the in-memory `FakeServer` demo backend with simulated latency (everything resets on restart there). `--dart-define=LP_BACKEND=fake|firebase` overrides the platform default. **Every** contract switches on that provider now: auth, journey, community, coach, panic, moderation, and the server-state reads.

The **TypeScript Cloud Functions backend in `functions/`** is deployed and live on project `alastpuff`, and the app calls it through `LpFunctions`. See "Server (`functions/`)" below.

**`docs/08_Sprint_Tracker.md` is the live build board** — what is actually done, what is blocked, and the current targets ($44K/mo net by M6; **Android at launch Oct 15 2026, iOS a fast-follow** — since Sep 1 2026 a Mac with Xcode is on the desk, so iOS builds and runs on a physical iPhone with Sign in with Apple; what still stands between it and the store is tracked there). Read it before planning work; it supersedes the revenue and phasing numbers in `docs/01`. `docs/10_Build_Log.md` is the dated session log split out of it on Sep 2 2026 (cite `docs/10 §N`); `docs/11_AI_Flow.md` explains the coach pipeline and its per-turn economics; **`docs/13_Feature_Map.md` is the feature list** — every shipped user-facing feature with what it does and how to test it by hand, and the register of what is deliberately absent.

## Architecture

Strict MVVM with Riverpod 2.x `Notifier`s as view models, layered as a one-way dependency chain:

- `lib/domain/` — pure Dart, no Flutter imports. Models (`models.dart`, `journey_state.dart`, `enums.dart`), **async backend contracts** (`repositories/repositories.dart`: `AuthRepository`, `JourneyRepository`, `CommunityRepository`, `CoachRepository`, `PanicRepository`, `ModerationRepository`, `ServerStateRepository`, `UserContextRepository`, plus the `AuthException` types), the **analytics port** (`analytics/`: `AnalyticsSink` — write-only, so not a repository — and `extension LpEvents`, the one place the docs/02 §7 event names live), and the calculation engines in `logic/`: `TaperEngine`, `MoneyEngine`, `StreakEngine`, `DangerHours`, `DependenceEngine`. All displayed numbers come from these engines — the brand rule is "no invented numbers", so never hardcode a stat a mock shows.
- `lib/data/` — the backend-shaped stack, bottom-up:
  - `api/` — typed wire interfaces speaking `Map<String, dynamic>` JSON (`AuthApi`, `JourneyApi`, `CommunityApi`, `CoachApi`); `api/fake/` implements them over `FakeServer`, the in-memory JSON "database" (accounts, journey docs, posts; latency via `apiLatencyProvider`, tests override to zero). **FakeServer invariant: every op mutates synchronously, only the ack is delayed** — this keeps write-behind clients and server-computed coach args consistent.
  - `dto/` — hand-rolled JSON codecs (`JourneyCodec`, `PostCodec`, `CoachReplyCodec`, `codec_helpers.dart`). Day-map keys are `'yyyy-MM-dd'` **local midnight** (never epoch math); enums encode by `.name` with safe fallbacks. **Any new model field must be added to its codec AND `test/data/dto_roundtrip_test.dart`.**
  - `repositories/` — thin `Api*Repository` implementations of the domain contracts (JSON ↔ domain only, no logic), plus the real backend: `FirebaseAuthRepository`/`FirebaseJourneyRepository` (`firebase_common.dart` holds the shared journey-doc helpers and `guardAuth`, the ONE place Firebase/Google error codes map to the domain taxonomy — `network-request-failed` → `NoConnectionException`, dismissed native sheets → `SignInCancelledException`). The journey persists as a single Firestore doc `journeys/{uid}` of `JourneyCodec` JSON; guest onboarding falls back to anonymous auth. Both backends mint identical day-1 journeys via `domain/logic/journey_factory.dart` (`InitialJourney.build`).
  - `stores/` — Riverpod view models. `JourneyStore`: awaited async lifecycle (`logIn`/`register`/`signInWithApple`/`restoreSession`/`startJourney`; optimistic sync `signOut`/`deleteAccount`/`seedDemoJourney`), and **every other mutation is synchronous + optimistic through `_commit(next)`** = set state + `unawaited(save)` write-behind — views may read fresh state right after a command; keep new mutations on that pattern. `providers.dart` is the composition root and documents the backend swap point: REST replaces `api/fake/`, Firebase replaces either the Api or Api*Repository bodies; stores and views never change.
  - `analytics/` — the vendor half of the analytics seam. The port and the event vocabulary are in `lib/domain/analytics/` (`AnalyticsSink` + `extension LpEvents`); this folder holds one class per vendor (`AmplitudeAnalytics`, `FirebaseAnalyticsSink`), plus `FanOutAnalytics` (one event → every vendor) and `NoopAnalytics`. `analyticsProvider` in `providers.dart` is the only place the live list is named — **adding, dropping or swapping a vendor is one entry there**, never a call site. `AmplitudeAnalytics` is the only file in the app importing `package:amplitude_flutter`, and `repositories/revenuecat_billing_repository.dart` is the only one importing `package:purchases_flutter` — the billing seam is `BillingRepository` (fake: `FakeBillingRepository` over `FakeServer`, with `FakeServer.nextPurchase` scripting the store sheet). The store identifiers live in `domain/logic/billing_catalog.dart`, mirrored by `functions/src/domain/plans.ts` with parity tests; the RevenueCat public SDK keys live in `data/billing_options.dart`.
  - `seed/seed_data.dart` — the demo day-12 journey (single source; the fake backend serializes it through the codecs, so the JSON round-trip runs in production code).
- `lib/features/<name>/` — one folder per screen/flow. Views read state via providers and issue commands through `.notifier`. Async lifecycle CTAs pass `busy:` to `LpButton` and guard navigation with `mounted` after awaits.
- `lib/app/` — `router/app_router.dart` (go_router with a `StatefulShellRoute` 4-tab shell: Home/Stats/Community/Coach; all route paths live in the `Routes` class) and the theme. The router redirects journey-requiring paths to `/auth` while `journey == null`, but **deliberately allows authed visits to `/auth` and `/onboarding`** — don't "fix" that; onboarding is re-enterable and the sign-in screen must stay reachable for an authed user switching accounts. Lifecycle callers must set journey state **before** navigating into gated paths (awaiting the store call does this).
- `lib/core/` — shared widgets (`LpCard`, `LpChip`, charts, `RollingNumber`, `ProgressRing`, `NewIdConfetti`, `PushPreviewCard`, …) and utils. **All price strings live only in `core/utils/lp_pricing.dart` (`LpPricing`)** — reuse, don't duplicate.
- **Panic games** (docs/10 §15): three engines in `lib/domain/logic/games/` (`TileGame`, `BlocksGame`, `OrbsGame`), all pure Dart and seeded, behind `PanicGame`; `GameSession` is the one clock (60-second rounds chained to five, `maxStep` clamp, the last step cut at the line). The widget side is `features/panic/game_arena_screen.dart` + `features/panic/games/` — `GameCatalog` is the only seam, so a new game is an engine, a field (gesture layer + `CustomPainter` off the `FrameClock`) and one catalog entry; the arena never switches on a game, it reads `GameFeedback` off events. **Orbs is free and `entries.first`; Tiles and Blocks are Premium** (docs/12 §5c) — and `entries.first` is load-bearing, because `GameCatalog.resolveFor(id, premium:)` clamps a stored `lastGame` or a `?g=` link to a free game, so nobody ever *lands* on a lock mid-craving. The lock card is the one paywall door anywhere in panic, it leads with "Play Orbs", and it never appears mid-round. No Flame, deliberately (§7 row 19). Blocks is its own expression, never Tetris's (§7 row 20). Bests live per game in `JourneyState.gameBests`; a round is recorded only when it ran to the end.

- **Cirrus on the wrist** (`ios/CirrusWatch/`, `ios/CirrusWatchComplication/`, docs/10 §29): a watchOS app plus a watch-face complication, and **a third renderer of the same mirror rather than a second app**. `CirrusShared.swift` and `CirrusOutbox.swift` are members of the widget target, both watch targets and Runner — one file each, four readers — so the taper curve, the day clamp, the seven-day limit window and the no-journey refusals have exactly one implementation. **The one genuinely new problem is that an App Group is per-device**: the identical group string resolves to a different store on the watch, so `WatchWire.swift` (Foundation only, no WatchConnectivity import) is the protocol both sides speak — `updateApplicationContext` carries the mirror document verbatim, `transferUserInfo` carries the queue back, and the phone's `ios/Runner/CirrusWatchLink.swift` relays each tap through `CirrusOutbox.append(delta:at:)` so it becomes an ordinary outbox row `WidgetCoordinator` drains like any widget tap. That absence of a WatchConnectivity import is load-bearing: it lets `test/ios_watch_contract_test.dart` compile the wire with `swiftc` and **play both devices in one process**, so the whole two-device loop is provable from `flutter test`. The Dart seam is one method, `WidgetStore.syncWatch()`. Targets are generated by `tool/ios_watch_target.rb`, idempotently, and enter no scheme.

### Server (`functions/`) — deployed and live

TypeScript Cloud Functions 2nd gen on `alastpuff`, us-central1. `index.ts` is a thin barrel of 24 exports: `aiCoachChat`, `panicSession`, `syncUserContext`, `deleteUserData`, `createPost`, `createReply`, `reportPost`, `reportReply`, `moderatePost`, `moderateReply`, `remoderateHeld`, `moderationQueue`, `resolveModeration`, `onReaction`, `coachMemories`, `forgetCoachMemory`, `seedCoachMemories`, `setCoachName`, `matchedTestimonials`, `taperRecalc`, `weeklyInsight`, `pruneDevices`, `rcWebhook`, `refreshEntitlement`. (`dangerHourPush` from docs/05 §7 is deliberately absent — danger-hour reminders are deterministic, so they're scheduled on-device.) The pipeline and its cost per turn are explained in `docs/11_AI_Flow.md`. Layout: `ai/` (the `TextModel` seam — only `ai/gemini.ts` imports a vendor SDK, so swapping providers is one new implementation; all prompts live in `ai/prompts.ts`), `domain/` (a TS port of the Dart engines), `handlers/`, `lib/`, `config.ts` (secrets/params via `defineSecret`/`defineString`; production values in the committed `.env.alastpuff`).

**Five things that will bite you here, each of which already did:**

1. **`LpFunctions` (`data/api/firebase/functions_client.dart`) is the only door** from the app. It injects the IANA timezone and locale that every callable's `requireCaller` reads, and maps wire failures to the domain taxonomy. Never call `FirebaseFunctions` directly.
2. **Every callable sets `enforceAppCheck: true`,** so a token the backend will not accept breaks *everything* at once — coach, panic, community, user sync — and it does not look like an App Check problem. The debug secret used to rotate on every install, and `flutter test integration_test` uninstalls the app when it finishes, so a token registered after a run was already stale. It is **pinned** now: `AndroidDebugProvider` takes a `debugToken`, supplied via `--dart-define=LP_APPCHECK_DEBUG_TOKEN` from the gitignored `.appcheck_token` (a registered debug token bypasses attestation project-wide, so it is a credential). Use `./tool/device.ps1` so the define is never forgotten; on macOS (no PowerShell) launch with `--dart-define-from-file=.dart_defines.json` by hand, after registering the same token for the **iOS** app id too — the two Firebase apps are separate registrations, and a token known to only one of them fails every callable on the other platform (the `appcheck:*` commands need firebase-tools 15+; use `npx firebase-tools@latest` if the installed CLI is older). **A gen-2 callable answers a failed App Check with the same `unauthenticated` it uses for a missing user** — that is why `mapCallableError` disambiguates on whether anyone is signed in, and why `BackendRejectedException` exists rather than folding into the offline copy.
3. **A sideloaded `--release` APK can never pass App Check, and no define changes that.** `flutter build apk --release --dart-define-from-file=.dart_defines.json` looks correct and is not: `kDebugMode` is false in a release build, so the pinned token is read into a constant nothing consults and the app attests with **Play Integrity**, which cannot vouch for an APK Google has never seen. No token is minted, the SDK sends something that is not a JWT, and the backend rejects *every* callable with `Decoding App Check token failed` — coach, panic, community, testimonials, user sync, all at once, none of it looking like App Check. It was silent because `logAppCheckStatus()` opened with `if (!kDebugMode) return;`. Both halves are fixed: the diagnostic runs in every build mode, and `activateAppCheck()` announces a debug token handed to a non-debug build (`test/app_check_diagnostics_test.dart` pins both, and that the debug provider stays debug-only — the fix must never become "let release use the token", which would ship a project-wide attestation bypass inside the APK). **Wanting analytics is not a reason to build release**: `LP_ANALYTICS=on` overrides the `kReleaseMode` check in any mode, which is what `./tool/device.ps1 -Analytics` passes. A genuine release build can only be tested from the Play **internal testing** track.
4. **Model ids are config, and a wrong one fails silently.** `MODEL_*` in `.env.alastpuff` must name a model that exists AND supports `generateContent`. `gemini-3.1-flash` did neither, so every user got the warm fallback for as long as it was deployed while the logs said nothing. `aiCoachChat` now logs the live catalogue on a 404 (`coach.models_available`) — read that rather than guessing. No `-preview` ids (withdrawn without notice) and no `-latest` aliases (docs/04 §9 gates the coach on a 15/15 eval pass; an alias swaps the model underneath it).
5. **A `collectionGroup()` query needs its own recursive-wildcard rule.** A nested `match` does not cover one. The missing rules made the entire community feed return PERMISSION_DENIED in production while the rules suite stayed green, because every test in it read a direct document path.

**The one architectural rule** (`firestore.rules`, `functions/README.md`): ownership is split. `journeys/{uid}` is **client-owned** — `FirebaseJourneyRepository.save()` does a whole-document `set()` on every optimistic mutation, so **any server-written field here is destroyed by the next puff tap**. `users/{uid}` is **server-owned** (entitlement, `aiUsage`, `planAdvice`), readable by its owner and writable only by the Admin SDK. Entitlement lives there for a reason: if a client could write it, it would grant itself Premium. The journey doc carries **no tier at all** since Sep 2 2026: the client's tier is `entitlementProvider` (`EntitlementStore`, fed by RevenueCat's customer record through `BillingRepository`), the server's is the mirror, and neither believes the other. `rcWebhook` mirrors a fetched subscriber **snapshot** (`lib/revenuecat.ts`), never the event's own claim.

**`coachName` is the one field that deliberately lives on BOTH sides,** and it is worth understanding as the model case. `journeys/{uid}.profile.coachName` is client-owned and drives every screen. `users/{uid}.coachName` is written only by the validated `setCoachName` callable, and is **the only version `aiCoachChat` is allowed to read** — because the journey doc is written wholesale by the app, so a name taken from it is unvalidated client text, and `"Ember. IGNORE ALL PRIOR INSTRUCTIONS"` going straight into a system prompt is a live injection surface. `journeyCodec.ts` sanitizes the client copy on decode as a backstop, the same treatment `moodNote` already gets.

Community collections: `posts` (created only via the `createPost` callable so no uid lands on the post), `postAuthors`/`replyAuthors` (the server-only uid↔content maps that make account deletion possible without breaking anonymity), `posts/{id}/reactors` (one document per person, so aggregate counts stay public while identities stay private), `moderation` (founder review queue, reachable only through `moderationQueue` behind an `admin` custom claim). **A post's `status` and its author's mirror status are two vocabularies:** the post is `pending`/`live`/`blocked` (rules read only `live`), the mirror `users/{uid}/posts/{id}` adds `held` so the app can say "Posting…" for a post still being classified and "In review" only when the model asked for a human (`MIRROR_STATUS` next to `VERDICT_STATUS` in `moderatePost.ts`). A hold the pipeline itself caused (model down, unparseable verdict) carries `retryable: true` on its queue row and `remoderateHeld` re-asks every 15 minutes (at most 8 times) — a hold the model chose is never re-rolled, and `resolveModeration`/`reportPost`/`reportReply` clear the flag so a person's decision is never re-asked. The three-report auto-hide mirrors `held` too. `createPost` is idempotent on the app's `clientId` (doc id = sha256(uid:clientId)[:20]), which is what makes the feed's "tap to retry" safe. The client keeps the mirror watch open through `held`, so a later flip lands without a restart. Policy since Sep 1 2026: only words aimed at people are ever hidden; "fuck this app" publishes. `npm run eval:moderation` gates any prompt change.

**Ember's long-term memory** is `users/{uid}/memories` — one document per remembered fact with a 768-dim `embedding`, searched with `findNearest` (`lib/memories.ts`). It sits under `users/{uid}`, so `deleteUserData`'s `recursiveDelete` already erases it. It complements, never replaces, the deterministic user card in `ai/memoryCard.ts`: anything derivable from the journey belongs in the card, which is exact and costs nothing, and the vector layer is only for things a user said out loud.

### Error handling

Every failure has a designated friendly surface — never invent per-screen phrasing or let an error escape raw:

- **Taxonomy**: repositories throw `NoConnectionException` (offline) or auth-specific `AuthException`s (`domain/repositories`). `data/network/connectivity.dart` answers "online?" from three signals — the OS transport stream (`connectivity_plus`, instant and event-driven: no interface means offline, held 1.2s so a wifi→cellular handover never shows), a parallel two-host DNS probe (polled every 10s in the foreground, re-asked the moment a transport appears or the app resumes), and the app lifecycle (no probing in the background). **One failed probe is never a verdict**: going offline with an interface up takes three straight failures 1.5s apart; coming back takes one success. `FakeServer` reads the store synchronously and becomes unreachable offline, exactly like a real backend.
- **Surfaces** (all in `core/widgets/lp_error.dart` unless noted): app-level offline pill overlaid via `MaterialApp.builder` (`OfflineBanner`); `showLpErrorDialog(context, error:, onRetry:)` for awaited lifecycle CTAs — `lpErrorCopy` picks offline vs generic copy; `LpErrorState` for failed content areas (community feed pattern: `FeedStatus` + `retryFeed()`); go_router `errorBuilder` → `RouteNotFoundScreen`; the coach fails in-thread via `CoachTemplate.connectionLost` (and refunds the free message); `LpCrashScreen` (core/widgets) replaces the red error box — it may render in a broken tree, so it's the ONE place with non-ARB copy and raw palette hexes (annotated); `LpErrors.install()` (app/app_errors.dart, called in main) routes uncaught async errors to a throttled "backstage" snack.
- **Local-first stance**: optimistic mutations `.ignore()` wire failures (`_commit`, community write-behinds) — the banner tells the story; never surface a dialog for a background save. `restoreSession` failure lands on sign-in, never a stuck splash.
- **Tests**: anything that pumps the app or wires the fake backend must use `fastBackendOverrides()` from `test/helpers.dart` (pins `BackendMode.fake` — the test platform reports android, which would otherwise construct the Firebase repositories — plus zero latency + polling off; `online: false` simulates airplane mode). No Firebase mocks anywhere. Error surfaces are covered in `test/widgets/error_handling_test.dart`.

### Testing

Four layers, and each catches something the others structurally cannot:

- `flutter test` — unit + widget. Fast, runs everywhere, and the only one CI gates on for the app.
- `flutter test integration_test -d <device> --dart-define=LP_BACKEND=fake` — **the real app on a real device.** The only harness that sees disposal, the router, a torn-down tree, or a keyboard. It found three bugs no widget test could have.
- `integration_test/f_firebase_backend_test.dart` with `LP_BACKEND=firebase` — **writes to production.** Creates one throwaway account in `setUpAll` and deletes it in `tearDownAll`. Read `integration_test/README.md` first: App Check makes this fiddlier than it looks.
- `functions/`: `npm run verify` is the deploy gate (typecheck + lint + vitest). `npm run test:rules` (42) and `npm run test:integration` (163) need the Firestore emulator, which needs Java — **Android Studio ships one**, so they run here:
  ```
  export JAVA_HOME="/c/Program Files/Android/Android Studio/jbr"   # PowerShell: $env:JAVA_HOME=...
  export PATH="$JAVA_HOME/bin:$PATH"
  ```
  Two traps in the integration suite, both of which cost a debugging round: deploy-time params resolve to **0** with no `.env` loaded (a coach `limit` of 0 makes every call answer `capReached` before reaching the model, so stub them), and `vi.useFakeTimers()` freezes the timers the Firestore SDK itself runs on — use `toFake: ['Date']` or every await hangs to the timeout.

Anything that pumps the app must use `fastBackendOverrides()`; see the Error handling section.

### Demo model (fake backend only)

**Ember's follow-up chips do not exist here.** `aiCoachChat` returns 3-4 things the *user* might say next (docs/11 §3), written per turn from the last exchange; the fake coach returns none, so `LP_BACKEND=fake` always shows the four static `CoachChip`s. That is also the honest production fallback — an older backend, a restored transcript, the cap, and every mid-craving turn all show the static four — but it means the feature can only be *seen* on a device against real Firebase.

The sign-in screen gates its identity buttons by `defaultTargetPlatform`: Apple on iOS/macOS, Google on Android, email everywhere. On the fake backend, email login (any email; password < 6 chars = "wrong", enforced in `FakeAuthApi`, not views) restores the seeded day-12 journey (@quietfox). "Sign in with Apple"/register open a fresh account → onboarding (21 `ObStep`s) → paywall → the backend creates the day-1 journey. Within one app session, mutations persist across logout→login (write-behind JSON on `FakeServer`); registering the demo email `maya@quitmail.com` fails as already-in-use. `seedDemoJourney()` is synchronous — don't make it await. **The Frame Map is deleted** (Sep 3 2026, docs/10 §18): it was `kDebugMode`-gated in Settings but its routes were registered unconditionally, so both its screens shipped in every release binary and were reachable by deep link.

### Theming

**Three palette FAMILIES × two modes = six `LpColors` instances**, one `ThemeExtension`. `LpPalette` (`app/theme/lp_palette.dart`) picks the family, `ThemeMode` still picks light/dark/system inside it — **the two axes are orthogonal, and that is why "Match system" survives for a subscriber.** `MaterialApp` takes exactly two `ThemeData`s and `ThemeMode` has exactly three values, so a flat list of six would have cost the system option outright. Settings has two rows: **Appearance** (mode — "Match system"/"Dark"/"Light", never a family name) and **Theme** (family).

- **Ember** — free, the brand default and byte-frozen by `test/app/lp_palette_test.dart`. `LpColors.midnight()` / `.daylight()`.
- **Hearth** — Premium. Warm, amber primary on charcoal/linen (`.hearthNight()` / `.hearthDay()`).
- **Tide** — Premium. Cool, teal primary on indigo/arctic (`.deepTide()` / `.arcticTide()`).

**The tokens are hue-NAMED but role-USED.** `volt` means "the primary accent", not "lime"; `onVolt` is "ink on the primary fill". A family repaints the slots and never renames them, which is why adding two families changed no widget. `danger` is deliberately the same `0xFFFF5C5C` in all six — an alert must not change meaning when the reader changes their theme.

**The family is clamped on RENDER, not on selection** (`LpPaletteCatalog.resolveFor`, shaped on `GameCatalog.resolveFor`, and `LpPaletteCatalog.entries.first` must stay free for the same reason Orbs is). `LastPuffApp.build` resolves against `isPremiumProvider`, so an expiry re-themes the app back to Ember by itself while the stored choice survives untouched — resubscribing brings their palette straight back. The picker refuses to store a locked family; only a lapse can produce that state.

Widgets read semantic tokens via `context.lp`; **never raw hex in widgets** (the only sanctioned exception is annotated: the Apple sign-in button. The iOS rating-sheet link blue went with the fake StoreKit pastiche it existed for). `lp.caution`/`lp.cautionText` are the only sanctioned yellows. **`LpChip` maps accent colors to text tokens by COLOR EQUALITY** (`accent == lp.ember ? lp.emberText : …`) — pass `selectedColor: lp.oxygen`/`lp.ember`, never a text color, and never let two accents in one palette share a value or that dispatch silently picks the wrong token in that palette only (pinned per family). Fonts: Space Grotesk (display) + Inter (body), bundled in `assets/fonts` — shared by every family, only colors vary.

The home-screen widgets do **not** follow any of this, differently per platform. Android mirrors Ember's hexes in `cirrus_widget_colors.xml` and follows the *system* theme, because the launcher inflates it in its own process against its own configuration. iOS (`ios/CirrusWidget/CirrusWidget.swift`) wears Midnight Ember always — a WidgetKit view draws itself — and `test/ios_widget_test.dart` pins its annotated hexes against `lp_colors.dart`. The **Apple Watch app** (`ios/CirrusWatch/WatchPalette.swift`) does the same, pinned the same way by `test/ios_watch_test.dart`, and on a watch it is also simply correct: watchOS has no light mode. Its **complication wears no palette at all** — a watch face tints its own complications and the person chose that tint, which is the same reason the iOS lock-screen families are bare. All documented deviations, not omissions.

### Localization

Zero hardcoded UI strings. ARB files in `lib/l10n/app_{en,es,fr,de,pt}.arb`, generated into `lib/l10n/gen` (never edit generated files). Use `context.l10n` (`core/utils/l10n_ext.dart`). Content that lives in data is stored as ids/enums and resolved to l10n in views: coach replies via `CoachTemplate` enums, community seed posts via `seedTextId`, seeded goal names via ids (g1/g2 — the demo journey only; real goals carry the user's own words). ARB templates must not add symbols around already-formatted values (e.g. no extra '%' around a formatted percent). **A string that interpolates a user-supplied name must be grammatically valid with that name treated as an indeclinable proper noun requiring no article, no elision and no gendered agreement** — pt drops the article on both sides, fr never elides and repeats `{name}` rather than using `il`, de avoids the genitive-s. `test/coach_name_test.dart` renders all 14 name-bearing keys × 5 locales × 3 probe names to enforce it, and `test/l10n_parity_test.dart` pins that every locale interpolates exactly the values English does — a translator dropping a `{placeholder}` compiles fine and silently renders a sentence with a hole in it.

## Gotchas (each was a real bug — don't reintroduce)

- `TweenAnimationBuilder` with a begin-less `Tween(end:)` never animates its first build — `RollingNumber`, `GlowProgressBar`, `BarChart`, `ProgressRing` all carry an explicit `begin`.
- `BarChart` must fold (not `reduce`) — callers pass runtime `List<int>` into a `List<num>` param and `reduce`'s covariant `combine` throws.
- `StreakEngine.currentStreak` skips an unconfirmed today (anchors to yesterday) so an in-progress day dims the flame instead of zeroing it — unit-tested.
- Seed data: a day's actual puffs must stay ≤ that day's curve limit or the streak chain silently breaks.
- `PanicFlow` clears snackbars on entry (the 5s undo snack otherwise outlives the route push and covers "Skip to my why").
- `showLpSnack` carries a fallback timer that force-closes the snack at `duration + 250ms` — the framework skips its own timeout for action snack bars under accessible navigation (which some environments report spuriously), leaving "Undo" snacks up forever. Don't remove it; route all snacks through `showLpSnack`.
- **A bare `Column` overflows the moment the viewport shrinks.** Auth forms use `_AuthScrollView` and onboarding steps use `StepScrollView` — both scroll under a min-height + `IntrinsicHeight`, which preserves the `Spacer()`s that pin a CTA to the bottom. The path that catches it: registering opens the keyboard and `context.go(Routes.onboarding)` runs before the IME is dismissed, so step one renders into what is left.
- The FakeServer's connectivity gate reads the connectivity store **synchronously** (never await a probe inside `respond`) — an async gap there breaks the sync-apply invariant.
- App-pumping tests without `fastBackendOverrides()` do real DNS lookups and leak the 5s poll timer.
- **Never write a server-owned field onto `journeys/{uid}`.** The client `set()`s the whole document on every optimistic mutation, so the next puff tap silently destroys it. Server state goes in `users/{uid}`.
- **Two implementations of the same math drift, and already have** — `streakEngine.ts` once omitted the repair-token exception `streak_engine.dart` applies, so the server counted a token-saved day as a break. Fixed and pinned by parity cases on both sides. Any change to a shared engine must land in both `test/domain/*_test.dart` and `functions/test/*.test.ts`, or the coach starts quoting numbers the Home screen contradicts.
- `CoachReplyCodec.decode` must keep reading `text` — it once read only `template`/`args`/`showWeekCard`, so every word the model said was discarded and rendered as the canned `generic1` template. A blank `text` decodes to null so it can never render an empty bubble.
- **`IntrinsicHeight` asks its child for a max intrinsic height, and that walk reaches everything below it.** A `FractionallySizedBox` whose factor animates from 0 reports an infinite intrinsic height on the first frame, which fails layout outright. It took the whole Health screen down for every user past day 1. Prefer a `Stack` with positioned children — they are excluded from intrinsic sizing and get bounded constraints.
- **A `refreshListenable` fires AFTER the frame, so navigate before you mutate.** The paywall set the tier and then popped; Riverpod delivered the router's refresh a microtask later, the match list was rebuilt, and the imperatively pushed route came back — `canPop()` returned true, the pop visibly did nothing, and the user was left on the paywall they had just paid past. `leavePaywall()` runs first, the state change second. The community composer fell into the same hole a month later: `addPost` awards the `firstPost` badge (a journey mutation) and the pop after it was undone — on every account's first post only, which is why it looked intermittent. Any screen that mutates the journey and leaves: leave first.
- **`open(path, 'w')` truncates before the write that fails.** Editing an ARB with line surgery destroyed 432 lines of `app_en.arb` when a surrogate pair failed to encode mid-write, and emptied `frame_map_screen.dart` when a stray comma made the payload a tuple. Edit ARBs through a JSON round-trip, and write every generated file to a temp path then `os.replace`.
- **Never invent data that renders as the user's own.** `InitialJourney` used to mint a savings goal ("Tokyo flight") and a buddy ("Sam") for every account; the Insight screen used to show four authored "findings" about the reader. Both read as the user's own data and both broke the no-invented-numbers rule harder than a wrong stat would. An honest empty state is always the right answer.
- **A control that only shows a success snack is worse than a missing one.** Export, Restore Purchases and the buddy ping all claimed to have done something and did nothing. If it cannot do the thing, it does not ship.
- `flutter test` substitutes a fixed-width fallback font, so **widget tests overflow where the device does not**. `screen_layout_test.dart` therefore excludes overflow and asserts only on the font-independent failures (infinite/unsatisfiable constraints, unlaid-out boxes). Real overflow is caught on device.
- **A local notification must be `zonedSchedule`d.** `periodicallyShow` repeats every 24h *from the moment it is called* and ignores the hour and minute entirely, so the danger-hour reminder fired at whatever moment the app last synced — planner correct, coordinator correct, feature silently useless. And build the next occurrence as the next CALENDAR day: `add(Duration(days: 1))` adds 24 absolute hours, which moves the reminder an hour across a DST boundary.
- **`flutter_local_notifications` needs TWO receivers in the app manifest, and must never need an exact alarm.** Since the plugin's v16 its own manifest ships only `POST_NOTIFICATIONS` and `VIBRATE`; `ScheduledNotificationReceiver` (what `AlarmManager` delivers every scheduled notification to) and `ScheduledNotificationBootReceiver` (which re-arms them after a reboot or an app update) are the host app's job. Neither was declared, so every `zonedSchedule()` armed an alarm that fired into an undeclared component — no notification, no error, planner and coordinator both correct. The other half of the same manifest: `SCHEDULE_EXACT_ALARM`/`USE_EXACT_ALARM` were declared and never used (both calls pass `AndroidScheduleMode.inexactAllowWhileIdle`, the one plugin branch that never checks the permission), and Play rejected the Sep 2 2026 submission for it. **The two are not the same door.** `USE_EXACT_ALARM` is closed — calendar and alarm-clock apps only. `SCHEDULE_EXACT_ALARM` is *open* to us (Play names it as the fallback), but it is denied by default on Android 14+ and can only be granted by sending the user out to Settings → Special app access → Alarms & reminders, and it stays revocable, so the inexact path survives either way. **Founder decision Sep 2 2026: we do not take it** — a settings trip is too much to ask for a nudge, and the timing lever without a permission is `ReminderPlanner.leadMinutes` (an inexact alarm may run late, never early, so a longer lead moves the whole landing zone earlier). Reminders are inexact by design: the nudge leads the risky hour by 10 minutes. `test/android_manifest_test.dart` pins all of it, both directions (docs/10 §16).
- **A widget test that reads the real `DateTime.now()` passes in the morning and fails at night.** Home picks ONE card from a priority chain (slip → mood prompt → craving nudge) and `showMoodPrompt` is `mood == null && now.hour >= 18`. The seeded day-12 fixture logs no mood for today, so `premium_gate_test`'s nudge case counted zero `Dismissible`s from 6pm local and the suite went red on the clock, not on a change. Put the fixture on the branch under test (check a mood in) rather than trusting the hour the suite happens to run at.
- **The frame map is `kDebugMode`-only.** It opens every screen and seeds the demo day-12 fixture for anyone without a journey, which then syncs to Firestore like any other mutation. It was reachable from Settings and from the sign-in screen, before sign-in.
- **Riverpod forbids `ref` in `dispose()`.** Capture the notifier in `initState` instead. Doing it the other way threw on every close of the panic flow — and hid a second bug, because `survive()` invalidates the provider, so a late `ref.read` would hand back a fresh, unresolved session.
- Counters that gate a UI decision must be **keyed by the thing they count**. `CommunityStore.reportPost` used one int across the whole feed, so reporting three *different* posts hid the third on its first report.
- **A day key is calendar arithmetic, never `Duration(days: n)`.** `LpDate` (`lib/domain/date_key.dart`) mirrors `functions/src/domain/dateKey.ts` name-for-name and is the one place local midnight is computed. `StreakEngine` used to walk the chain with `cursor.subtract(const Duration(days: 1))` — 24 *absolute* hours — against a map keyed by local midnight, so on a DST day it landed on 23:00 or 01:00 of the previous date, missed the key, and **reset every user's Freedom Streak to zero, twice a year**. Reproduced at 10 days → 3. The zone is implicit on the client and must never become a parameter: the moment a caller can pass one, some caller passes UTC.
- **Neither store lets you ask for a rating before the system prompt.** Apple 1.1.7 and Google Play's In-App Review policy both prohibit review gating, and Play forbids asking the user's opinion at all before presenting the rating card — including a star picker that routes every value identically. The five-star row on D3 belongs to the *testimonial*, not to the user. And neither OS reports whether its sheet appeared or what happened, so nothing may claim a rating was submitted.
- **`Ember` is also a palette token and a wire value.** `lp.ember`/`emberSoft`/`emberGlow`, `CoachRole.ember` (encoded by `.name`, so renaming it reclassifies every stored message) and one of the eight `_randomAlias` adjectives. A repo-wide find-and-replace takes all of them; `test/coach_name_test.dart` guards against it.
- **Analytics reports from the release app only.** `analyticsEnabled()` gates on `kReleaseMode`, not `!kDebugMode` — the launch gates and the >15% drop-off alert are read straight off this funnel, so a profile build and every `flutter test` must not appear in it as a user. Consequences: every `./tool/device.ps1` run is silent (verify on device with `--dart-define=LP_ANALYTICS=on`), no vendor SDK is constructed outside release so the API key never leaves a dev machine, and `flutter test` never reaches a `MethodChannel` that is not there — which is why `fastBackendOverrides()` needs no analytics stub (pass `analytics: RecordingAnalytics()` when a test wants to assert on the funnel).
- **`Amplitude(...)` is not ready when it returns.** The constructor fires a MethodChannel `init` and returns immediately; the Android plugin answers any earlier `track` with `IllegalArgumentException: Amplitude instance ... not found`. A sink may never throw at its caller, so the event is swallowed and lost — and the events at risk are the earliest ones, since the first screen view fires on the frame that builds the sink. `AmplitudeAnalytics._guard` chains every call onto `isBuilt`; `test/analytics_test.dart` fails if that chaining is removed.
- **A screen name must never be able to carry user text.** `LpAnalyticsObserver` reads `RouteSettings.name`, which go_router fills with `state.name ?? state.path` — the path *pattern* (`/community/:id`), not the filled URL, because no route declares a `name:`. Giving a route a `name:` changes what the analytics dimension records. And `StatefulShellRoute.indexedStack` switches tabs without pushing a route, so no observer sees it: `AppShell` reports those four itself.
- **A tap on LOG PUFF is one puff. Always.** The accelerating tap ramp (+1,+1,+1,+2,+2,+3,+3,+5…) turned 18 rapid taps into 68 logged puffs in the Aug 31 QA pass while the store fired exactly once per pointer-up; the ramp is gone, the burst only groups taps for Undo, and "I had ~30" is a press-and-hold that ticks one puff at a time. `test/widgets/log_puff_tap_test.dart` pins N taps == N puffs.
- **The repair-token wallet is derived from the day map, never stored-and-trusted.** It used to be recomputed as `streak ~/ 7` and clamped *up* to the stored value, which re-minted a spent token on the next commit and absorbed four slips off a two-token wallet. `StreakEngine.repairTokens` / `streakEngine.ts repairTokens` walk history (+1 per seven *completed* holding days, cap 2, −1 per token day; today can spend, never mint — minting mid-day funds a third absorb on the 21st day). Any fixture that wants a token has to have earned it in history.
- **"Is this post mine?" is a backend answer, per account.** A session-scoped set on the process-lifetime `FirebaseCommunityRepository` made the previous account's posts "mine" for the next sign-in on the same phone — and "mine" is the condition that hides Report/Mute/Block. Production reads the server-owned `users/{uid}/posts/{postId}` mirror (written by `createPost`, kept in step by `moderatePost`/`reportPost`/`resolveModeration`); the fake keeps its own `_postAuthors`. The mirror is also how an author sees "in review" instead of a post that vanishes.
- **Stats and the coach's week card window over calendar days (`DayWindow`), never over "the last N logged days"** — an unlogged day slid the whole chart into last week and made the day that most needed fixing unreachable.
- **The mirror's expiry is RevenueCat's horizon, never our own arithmetic.** `snapshotOf` counts a subscription when RevenueCat says `gives_access` and writes the later of the active entitlement's `expires_at` and the subscription's `ends_at`: a grace period is by definition past its period end, and Apple renews up to a day early (`ends_at` moves, `current_period_ends_at` does not) — re-deriving expiry from the current period revoked both. A 404, a timeout, a missing `RC_PROJECT_ID` are a 500 (retry), never a "free" row; `snapshotAt` orders concurrent deliveries.
- **`EntitlementStore` is generation-guarded.** `unbind()` forgets synchronously and bumps the session generation; an identify answer from an older generation is dropped, a bind waits for the in-flight reset, and stream events during the reset are ignored. `purchase()` binds before it trusts a held entitlement. An unconfigured SDK throws `StoreUnavailableException` from `identify` — a settled "free" is what shows a paying user the launch paywall.
- **RevenueCat's REST client speaks v2, and the key must be a v2 key.** The dashboard's "New secret API key" mints a v2 `sk_…`; `GET /v1/subscribers` refuses it with 403 `7243 "Secret API keys should not be used in your app"`, and the first device purchase proved it: the app showed Premium while `users/{uid}.entitlement` stayed null and RevenueCat's webhook log sat on "Retrying". `functions/src/lib/revenuecat.ts` is the only file that knows the URLs (`/v2/projects/{RC_PROJECT_ID}/customers/…`) and resolves RevenueCat's own ids (`prod…` → store identifier, `entl…` → `cirrus_pro`) with per-instance caches. `deleteSubscriber` treats 401/403 as a logged misconfiguration, never as a reason to trap someone in an account they asked to delete.
- **Every Premium gate is `LpPremiumGate`, and every door carries a `source`.** Insight, Health (nodes 8+), Stats (Month pill, 7-day clamp, forecast heatmap), Plan (adaptive door), Home (nudge is premium-only), Coach (cap CTA), the composer (non-SOS tags) and the once-a-day launch paywall (`LaunchPaywallPolicy`, splash) all read `isPremiumProvider` and push `Routes.paywallFrom(source)`. Two doors are deliberately hand-rolled rather than `LpPremiumGate`, and both say why in place: the panic arena's `_LockedGameCard` (`panic_game` — there is no started game to blur, and a blurred empty field is a lock over nothing) and the Settings theme picker (`theme` — the swatches ARE the real colours, so the locked card already shows the truth). **There is no `source` enum — the doc comment on `paywallViewed` (`domain/analytics/lp_events.dart`) is the only registry, and it has been stale once already.** Add a door, add it there. The server enforces what carries real cost (the coach cap, the posting allowance, `taperRecalc`) through `tierFor`, which reads the `users/{uid}.entitlement` mirror. **`ENTITLEMENT_MODE=mirror` since Sep 3 2026** (docs/10 §18) — before that it was `ungated` and every server limit was inert, so nothing was withheld from anyone and there was nothing to buy. The client gates still run off the store (`entitlementProvider`) and the server off its own mirror; neither believes the other, and `refreshEntitlement` is what stops the gap between them from metering someone who has just paid. A gate over a short surface must not overflow: `LpPremiumGate` keeps both children non-positioned so the Stack grows to the taller one.
- **`fastBackendOverrides()` seeds the paying demo persona by default.** The seeded day-12 journey has always been a subscriber's, and the fake's guest account starts with no entitlement row, so the helper puts the demo subscription on BOTH the fake server (what `insertPost` checks) and the store (what gates read). A test about a free account passes `premium: false`; forgetting it is how six unrelated suites broke when the gates landed.
- **The paywall shows only the plans the store offers.** A period missing from a LIVE offering gets no card and can never be the selection (the Test Store has no weekly product, and the weekly card once rendered the typed fallback price beside two live ones, under a "Founding price — locked forever" line that only exists with the founding offer). Fallback prices appear only when there is no offering at all, with the "prices unavailable" caption.
- **A notification tap routes on its payload.** Every scheduled reminder carries `ReminderKind.name`; `ReminderScheduler.opened` reports taps (including the cold-start one from `getNotificationAppLaunchDetails`) and `_ReminderSync` routes them — trial → trial-ending (or Settings once the trial is over), danger-hour → Home — but only after the splash has decided the first screen, because the splash ends in a `go` that would erase anything pushed before it.
- **The plugin's streaming callable loses the error code, differently per platform.** `cloud_functions`' Apple stream handler emits every failure as code `unknown` with only the SDK's `localizedDescription` ("Unauthenticated"); its Android handler emits nothing at all (`onError` just closes the stream). So an App Check refusal of `aiCoachChat` — the one callable that streams — read as "signal dropped" on both platforms while `syncUserContext`, over the plain `call`, correctly said "this build got bounced" on the same device. `callableErrorCode` recovers the code from the words when the code is `unknown`, and `FirebaseCoachRepository` re-asks over the plain `call` when a stream ends before a single word. Never let the stream path be the only classifier of a failure.
- **The home-screen widget must never outlive the session.** No journey — signed out, fresh install, account deleted, or a launch that restored nothing — means the empty card ("Start your plan"), never a count, a day number or working `+`/`−`. The home screen is visible to whoever picks up the phone, so this is the shared-phone leak in its most public form, and it breaks no-invented-numbers besides: those digits belong to nobody who is signed in. Five guards across two languages enforce it and all five are pinned (`widget_mirror_test.dart`, `android_widget_test.dart`; the Swift twins — `CirrusMirror.read` falling back to an empty mirror, `CirrusOutbox.append` refusing while `!hasJourney` — in `ios_widget_test.dart` and executed for real in `ios_widget_contract_test.dart`): `buildMirror` emits **no numeric keys at all** when the journey is null (absent, not merely flagged), `CirrusMirror.read` falls back to `absent` on a missing document / unknown schema / parse failure, `CirrusPending.append` refuses every tap while `!hasJourney`, and `CirrusWidgetProvider.build` hides `cw_active` and returns before setting a count or a tap target. Any new widget surface inherits the rule, and the **Apple Watch** did: `WatchHomeView` gates on `hasJourney` before it draws anything, the complication draws no number without one, and `ios_watch_contract_test.dart` runs the real Swift to prove a signed-out wrist shows words and refuses every tap. A watch is the most public form of this leak there is — it sits on a wrist all day in front of whoever glances at it.
- **Signing out has FIVE things to forget, and every one of them was a bug first.** A shared phone is the test: `analytics.reset()` (events under the last person's id), `EntitlementStore.unbind()` (inheriting their Premium), `WidgetCoordinator.discardQueued()` (their queued widget taps), `SettingsStore.resetMilestoneLedger()` (their settled badges) and `WidgetSession.unbind()` (the wrist). The last one is the sharpest: `celebratedMilestones` is device-scoped `SharedPreferences` with no uid in the key, and a badge marked settled makes `MilestoneReminderPlanner.plan` answer null **for ever** — so the next person got no milestone celebrations at all, silently. Anything new that is device-scoped but account-shaped belongs on that list, in `signOut` AND `deleteAccount`. **The fifth is the one that cannot be done synchronously at all** — an Apple Watch holds its own mirror and its own queue and may be out of range. It is also the one whose obvious implementation is wrong: the wrist forgets **only on a different `sid`**, never on `hasJourney: false`, because that same mirror is what every phone cold start pushes before `restoreSession` answers, and wiping on it threw away un-handed-over taps on every launch. Signing out therefore stops the numbers (the mirror says there is no journey) without emptying the queue; dropping the id here is what makes the *next* account's mirror look different, and `WatchWire.relay` refusing a batch whose `sid` is not the phone's own is what actually protects them in the window before that lands. An **absent** `sid` is not a change either — the first push of a cold launch can beat the app's own async uid lookup.
- **"Never initialised" is not "empty", and inferring one from the other breaks the opposite case.** `celebratedMilestones` starts empty for a user about to earn their first badge AND for one upgrading with a year of badges already earned — celebrate the first, stay silent for the second. `SettingsState.milestonesAdopted` is the flag that tells them apart; without it you either fire "Two weeks. TWO WEEKS." at somebody who did that a month ago, or you swallow their very first celebration. Any device-local ledger of "what have we already told them" needs the same flag.
- **A cross-store write has no transaction, so choose which way it fails and write that down.** `WidgetCoordinator._drain` advances its preferences cursor *after* the Firestore journey write becomes durable, so a process death in that window replays the puffs; advancing first would drop them instead. The ordering is deliberate — it fails toward "counted twice" rather than "silently lost" — and the reasoning is at the call site so nobody flips it thinking it is a bug. Closing it needs a two-phase intent record, which a sub-3-second crash window on the launch path has not earned.
- **A push preference has to live on the server, because the server is what sends.** `notificationsOn` used to cancel the locally scheduled reminders and tell the backend nothing, so every server push kept arriving on an app the user had just silenced. Preferences are `users/{uid}.pushPrefs`, written through `syncUserContext` (the existing server-owned door), and an ABSENT key reads as enabled so nothing needs migrating. The master switch also calls `PushService.deleteToken()`: that needs no network and no session, and is the half that actually guarantees this device goes quiet. The three flags are account-shaped state in device-scoped `SharedPreferences`, so they are the fifth thing on the sign-out forget list — see the `celebratedMilestones` entry above for why that list exists.
- **A notification's TAG is what makes twenty replies one line; the server throttle is what makes it one buzz.** Both halves are needed. A stable `android.notification.tag` per thread means a later send REPLACES the shade row instead of stacking — but replacing still re-alerts, so without `decideNotification`'s 90-second throttle the phone would show one line and buzz twenty times. `sosReply` is exempt from collapse on purpose: the news IS how many people came, and an author told that one person answered who never hears about the two who followed has been failed at the one moment the feature exists for.
- **Quiet-hours silencing is a CHANNEL swap on Android, never a per-message flag.** From Android 8 the channel decides sound, vibration and heads-up; `notification.priority` is accepted by FCM and ignored by the OS. Channel importance is also immutable after creation — `createNotificationChannel` on an existing id updates only the name and description, because the user owns that setting once they have seen it. So every category ships as a pair (`community_replies` + `community_replies_quiet`), **the ids are permanent**, and `messages` can never be deleted because the manifest names it as the default. And quiet never SUPPRESSES, only silences: that is what makes a wrong `tz` cheap. A missing `tz` must read as not-quiet — guessing UTC silences somebody in Sydney through their working afternoon.
- **The collapse read and write must be one transaction.** Two replies 800ms apart run in two concurrent function instances; a read-then-write lets both find the throttle lapsed and both send, which is the exact burst the throttle exists to prevent. Same warning `reportReply.ts` carries about its report counter.
- **An `@alias` does not identify a person, so mentions resolve inside the thread.** `_randomAlias()` mints from 5,760 combinations client-side with a plain `Random()` and no uniqueness check, into the client-owned journey doc, and the server never verifies the alias a caller posts under — two users collide at around ninety accounts. Matching against the people already in the thread is both cheaper and closer to what the writer meant. On a collision the FIRST claimant in the thread wins (the post's author precedes every reply), so replying under somebody's alias cannot steal their mentions or make them ambiguous enough to drop. Match by exact equality against a pre-tokenised set — never a regex built from a stored alias (`(a+)+$` is a denial of service in a Cloud Function), never `includes` (an alias of `a` matches nearly every reply).
